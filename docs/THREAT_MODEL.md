# 위협 모델

## 보호할 것

사용자가 검사할 파일, 로컬 파일 시스템, 컴퓨터 자원, 파일명·해시·검사 결과의 기밀성.
공격자는 파일 바이트, ZIP 항목 이름과 선언값, 다른 웹 페이지의 요청을 통제할 수 있다고 가정한다.

## 신뢰 경계와 방어

- 입력 파일 -> 불변 스냅샷: 일반 파일만 허용하고 64 MiB 제한. CLI의 심볼릭 링크는 거부하며 OS 지원 시 `O_NOFOLLOW`를 사용한다.
- ZIP -> 표준 파서: 중앙 디렉터리 최대 1 MiB·3,000개를 `ZipFile` 생성 전에 검사한다. 내용을 해제하지 않는다.
- ZIP 경로 -> 파일 시스템: 경로는 분석 데이터로만 사용한다. 어떤 항목도 디스크에 작성하지 않는다.
- 브라우저 -> 로컬 API: Host·Origin·Content-Type·Content-Length·크기·시간을 검사한다. 외부 URL 및 서버 파일 경로 입력을 제공하지 않는다.
- 보고서 -> DOM: `textContent` 사용, 제어 문자 가시화, 외부 리소스 없는 CSP. HTML 조립에 파일명을 삽입하지 않는다.
- 보고서 -> 파일: 사용자가 저장을 선택한 경우만 JSON 생성. CLI는 배타적 생성으로 덮어쓰기를 막는다.

## 탐지와 보장의 차이

ZIP 경로 탈출·특수 파일·겹치는 데이터·헤더 불일치·확장 폭탄 징후는 높은 위험으로 표시한다.
실행·암호화·중첩 항목은 정상 배포에도 있을 수 있으므로 그 자체로 악성 판정을 하지 않는다.
메타데이터가 정상인 악성 파일, 알려지지 않은 실행 포맷, 문서 취약점, 신뢰하지 못할 해시 원본은 방어하지 못한다.
압축 데이터만 바뀌고 헤더가 유지된 파일은 현재 검사에서 메타데이터 정상으로 나올 수 있으며,
실제 CRC 검사 없이 변조 없음으로 표시해서는 안 된다.

## 운영 전제

개인 로컬 사용 전용. 다중 사용자·기업 서비스로 공개하려면 인증, 요청 제한, 프로세스 격리,
자원 제한, 바이러스 엔진, 보안 업데이트·로그·사고 대응·법률 검토를 별도 설계해야 한다.
